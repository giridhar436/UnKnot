# UnKnot Phase 2: Backend & Full Application Integration

## Context

UnKnot has a complete Phase 1 frontend (Next.js 16 + React 19 + Tailwind v4). All data comes from `lib/mock-data/` through `lib/services/`. Auth is fake (setTimeout). No backend exists. Goal: replace all mock data with real Supabase-backed data, add Cloudinary file storage, Fireworks AI entity extraction, Context Engine for Ask UnKnot, and connect every page — without redesigning the UI.

---

## Step 1: Install Dependencies

```bash
npm install @supabase/supabase-js @supabase/ssr cloudinary pdf-parse-next zod
```

OCR abstraction layer created now; actual OCR provider chosen later by user.

## Step 2: Environment Variables

Create `.env.example` with: NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY, CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY, CLOUDINARY_API_SECRET, FIREWORKS_API_KEY, OCR_PROVIDER. Create `lib/env.ts` for server-side validation.

## Step 3: Supabase Clients

Create `lib/supabase/client.ts` (browser), `server.ts` (server components with cookies), `service.ts` (service-role, server-only).

## Step 4: Database Schema

Create `supabase/migrations/001_initial_schema.sql` with tables: **profiles**, **records** (main entity with category, record_type, document_date, status, duplicate_status, metadata jsonb), **files** (Cloudinary metadata linked to records), **extracted_data** (entities jsonb, queryable columns: amount, merchant, product, invoice_number, warranty_expiry, investment_type, is_investment), **relationships** (from_record → to_record with type), **reminders** (linked to records), **analyses** (question/answer/evidence). Enable RLS on all tables — every policy scoped to `auth.uid() = user_id`.

## Step 5: Authentication

Create `middleware.ts` (session refresh + route protection), `lib/actions/auth.ts` (signUp, signIn, signOut, resetPassword server actions). Modify `app/login/page.tsx`, `app/signup/page.tsx`, `app/forgot-password/page.tsx` to call real Supabase auth actions. Update `components/layout/sidebar.tsx` to show real user data and real sign-out.

## Step 6: Cloudinary Integration

Create `lib/cloudinary.ts` (server-only config + helpers). Create `app/api/upload/route.ts` (POST: validate auth, validate file type/size, upload to Cloudinary, create record + file rows in Supabase, trigger processing). Create `app/api/files/[id]/route.ts` (GET: return Cloudinary URL after ownership check).

## Step 7: Document Processing Pipeline

Create: `lib/services/pdf-parser.ts` (pdf-parse-next), `lib/services/ocr.ts` (OCR abstraction interface + Fireworks Vision implementation), `lib/services/extraction.ts` (Fireworks AI structured entity extraction with Zod validation), `lib/services/processing.ts` (orchestrator: PDF→parse→OCR if needed→extract→validate→store). Pipeline: Upload → determine type → extract text → Fireworks AI entity extraction → validate (Zod) → normalize → duplicate check → store → create relationships → generate reminders → mark completed.

## Step 8: Duplicate Detection

Create `lib/services/duplicates.ts`. Compare: document_date, merchant, amount, invoice_number, product. Score-based matching. Prioritizes document date over upload timestamp. Returns none/possible/high_confidence. Never auto-deletes.

## Step 9: Relationship Engine

Create `lib/services/relationships.ts`. Rule-based: same product across purchase+warranty→purchase_warranty, purchase+repair→purchase_repair, bill+payment→bill_payment. Store in relationships table.

## Step 10: Context Engine + Ask UnKnot

Create `lib/services/context-engine.ts` + `app/api/ask/route.ts`. Flow: question → intent classification (Fireworks AI) → extract key terms → query Supabase for relevant records → gather related records → build controlled context → Fireworks AI answer → validate no fabrication → return answer + source references.

## Step 11: Replace Service Layer

Replace contents of `lib/services/documents.ts`, `finance.ts`, `reminders.ts`, `ask.ts` to query Supabase instead of mock data. Function signatures stay the same so page components need minimal changes.

## Step 12: Connect Frontend

- `components/upload/upload-modal.tsx` — real file upload to /api/upload, real processing status, navigate to real document ID
- `components/ask/ask-view.tsx` — call /api/ask instead of mock
- `app/dashboard/page.tsx` — replace hardcoded "Giridhar" with real user profile
- `app/settings/page.tsx` — show real user data
- `app/documents/[id]/page.tsx` — use Cloudinary URL for file preview
- `components/layout/sidebar.tsx` — real user name/email, real sign-out

## Step 13: Documentation

Update `docs/architecture.md`, `docs/api.md`, `docs/progress.md`, `docs/phases.md` with actual implementation details.

## Step 14: Test

`npx tsc --noEmit`, `npm run lint`, `npm run build`. Manual E2E tests: signup → upload → processing → dashboard → ask → duplicate detection → RLS isolation → file retrieval.
